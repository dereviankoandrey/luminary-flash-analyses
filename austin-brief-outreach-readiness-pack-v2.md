## Current Blockers & Workarounds

### City Website Data Access (ONGOING)
**Problem:** Austin's website redesign has completely blocked direct URL access to meeting minutes, transcripts, and agenda documents since late July. All direct paths return 404 errors regardless of session number or URL pattern attempted:
- `services.austintexas.gov/edims/document.cfm?id=NNN` → returns raw PDF binary (not extractable)  
- `/council/sessions/NNN/meetings/MMM` → always 404 after site redesign
- API endpoints redirect to 302 with no usable data returned via curl/bypass

**Workarounds that could work:**
1. **Browser-based navigation only:** The council meetings hub (`austintexas.gov/council/meetings`) renders correctly in the browser, but clicking "Meeting Details", agenda links, and minutes links opens frame-based pages that require login or direct PDF access. No transcript extraction possible this way currently.
2. **Firecrawl configured** → enables reliable extraction of all Austin council documents including the frame-based meeting details pages AND session-level agenda/minutes at scale without browser overhead (~10-30s vs ~90s+ per document)
3. **Manual screen-scraper approach** — navigate each meetings details link individually via browser, wait for the iframe to load the PDF/HTML minutes page, extract text — extremely labor-intensive (5 min per meeting × 2 meetings/month = 10 hours/month). Not scalable but feasible for one-off production when Firecrawl is unavailable.
4. **Wait for staff memos published separately** — staff memos often get a standalone URL that survives the redesign better than transcript/minutes links; worth monitoring

**Action required from Andrey:** Configure `FIRECRAWL_API_KEY` in your environment variables to unlock reliable Austin data extraction. This has been a known blocker since Issue #13 (July 2026) and affects all subsequent brief production, outreach credibility ("we said this was live data"), and issue freshness.
